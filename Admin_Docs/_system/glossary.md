# 용어집

| 용어 | 쉬운 말 풀이 |
|---|---|
| 수집 워커 | 5분마다 서울시 API에서 121곳의 값을 받아 와 DB에 넣는 프로그램. 웹 서버와 따로 돈다 |
| 조회 API | 화면이 DB의 값을 달라고 요청하는 창구. 읽기만 한다 |
| 혼잡도 4단계 | 여유(1) · 보통(2) · 약간 붐빔(3) · 붐빔(4). 서울시가 정한 단계를 숫자로 저장한다 |
| 관측 시각 | 서울시가 그 값을 잰 시각(PPLTN_TIME). 수집한 시각보다 약 25 ~ 30분 이르다 |
| 지연(stale) | 관측 시각이 60분보다 오래된 상태. 화면에 "업데이트가 늦어지고 있어요"를 띄운다 |
| 스냅샷 | 어느 시각에 어느 장소가 몇 단계였는지 적은 기록 한 줄. 계속 쌓는다 |
| 시드 | DB에 처음 넣어 두는 기본 데이터. 여기서는 121곳의 이름 · 분류 · 좌표 |
| 마이그레이션 | DB 테이블 구조를 바꾸는 절차를 파일로 남긴 것 (Alembic) |
| 답 한 줄 | 화면에서 가장 큰 글자. "오후 4시부터 6시까지 여유로울 거예요"처럼 언제 가면 되는지 말한다 |
| 순수 함수 | DB나 시계를 쓰지 않고, 넣은 값만으로 결과가 정해지는 함수. 테스트하기 쉽다 |
| 무게중심 | 장소 영역(다각형)의 한가운데 점. API가 좌표를 주지 않아 이 점을 장소 좌표로 쓴다 |
| 하버사인 | 위도 · 경도 두 점 사이의 직선 거리를 구하는 공식 |
| 사전 생성 | 사용자가 오기 전에 페이지를 미리 만들어 두는 것. 빠르고 검색엔진이 읽기 쉽다 |
| Cache Components | Next.js 16의 방식. 데이터 함수에 "이 결과는 1분 동안 재사용"이라고 적어 두면 페이지를 미리 만들고 뒤에서 갱신한다 |
| proxy | 요청이 페이지에 닿기 전에 먼저 실행되는 코드(예전 이름 middleware). 없는 장소 코드를 404로 돌리는 데 쓴다 |
| 중계(route handler) | 브라우저의 `/api/...` 요청을 Next 서버가 받아 백엔드로 넘겨 주는 것 |
| 허용 목록 | 통과시킬 것만 적어 둔 목록. 중계는 화면이 쓰는 경로 7가지만 백엔드로 넘긴다 |
| 롤백 | 여러 줄을 쓰다가 실패했을 때, 그 묶음에서 쓴 것을 전부 없던 일로 되돌리는 것 |
| 캐시 이름표(cacheTag) | 기억해 둔 결과에 붙이는 이름. 그 이름으로 한꺼번에 지울 수 있다 |
| 서버 동작(Server Action) | 브라우저의 버튼이 서버에 있는 함수를 직접 부르는 Next.js 기능 |
| 별칭 사전 | "홍대" → "홍대 관광특구"처럼 사람들이 부르는 이름과 공식 이름을 잇는 표 |
