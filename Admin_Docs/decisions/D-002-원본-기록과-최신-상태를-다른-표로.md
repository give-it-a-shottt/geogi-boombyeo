# D-002 원본 기록과 최신 상태를 다른 표로

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]

무엇을: 5분마다 쌓는 기록(snapshots)과 화면이 읽는 "지금 값"(place_status)을 다른 표로 나눴다. 예측(forecasts)은 장소마다 최신 것만 둔다.
왜: 화면은 지금 값 121줄만 있으면 된다. 쌓이는 기록에서 매번 최신 줄을 찾게 하면 기록이 늘수록 느려진다.

## 개발자 상세

| 후보 | 장점 | 단점 |
|---|---|---|
| A. snapshots 하나만 두고 최신 줄을 조회 | 표가 적음 | 조회마다 "장소별 최신" 쿼리. 수집 실패 기록을 둘 곳이 없음 |
| B. 원본 + 최신 상태 분리 (선택) | 조회가 121줄 읽기로 끝남. 실패 횟수 · 사유를 최신 상태에 함께 둠 | 수집 때 두 표를 같이 써야 함(한 트랜잭션) |
| C. 시계열 전용 DB(TimescaleDB 등) | 대량 시계열에 강함 | 하루 3.5만 줄에는 과함 |

결정: B. `store_observation()`이 스냅샷 추가 · 예측 교체 · 최신 상태 갱신을 한 트랜잭션으로 한다.
제약: 지난 예측은 남지 않는다(예측이 얼마나 맞았는지 나중에 비교할 수 없음).
바꿔야 하는 조건: 예측 정확도를 분석하고 싶어지면 forecasts도 쌓는다. 스냅샷이 수천만 줄을 넘으면 월별 파티션을 검토한다.
