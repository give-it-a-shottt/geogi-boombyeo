# D-003 운영은 Postgres, 테스트는 SQLite

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]

무엇을: 실제 서비스는 Postgres를 쓰고, 테스트와 로컬 확인은 설치가 필요 없는 SQLite로 돌린다. 그래서 한쪽 DB에서만 되는 문법은 쓰지 않는다.
왜: 테스트가 도커나 DB 설치 없이 1 ~ 2초에 끝나야 자주 돌린다.

## 개발자 상세

결정 내용
- SQLAlchemy 2 ORM만 쓰고, `INSERT ... ON CONFLICT` 같은 DB 전용 upsert를 쓰지 않는다. "있으면 고치고 없으면 넣기"는 먼저 조회해서 처리한다(워커가 1개라 경쟁이 없다, D-001).
- 시각은 `UTCDateTime` 타입으로 감싸 SQLite가 시간대를 잃어도 꺼낼 때 UTC를 다시 붙인다.
- 테이블은 Alembic으로 만든다. 모델과 마이그레이션이 같은지는 테스트가 비교한다.

제약: Postgres에서만 생기는 문제(동시성, 타입 차이)는 테스트가 잡지 못한다. 실제 서버의 Postgres에서 수집 · 조회가 도는 것은 확인했다(2026-11-23, 121곳 최신).
바꿔야 하는 조건: Postgres 전용 기능(파티션, upsert, 집계 뷰)이 필요해지면 테스트도 Postgres 컨테이너로 옮긴다.
