# D-006 장소 121곳을 미리 만들고 1분마다 갱신

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]

무엇을: 홈과 장소 121곳의 페이지를 빌드할 때 미리 만들어 두고, 1분이 지나면 뒤에서 새로 만든다(Next.js 16 Cache Components). 121곳에 없는 장소 코드는 페이지에 닿기 전에 걸러서 404로 응답한다.
왜: 미리 만든 페이지는 빠르고 검색엔진이 읽기 쉽다. 수집이 5분 주기라 1분마다 갱신하면 충분하다.

## 개발자 상세

| 후보 | 장점 | 단점 |
|---|---|---|
| A. 요청마다 서버에서 새로 그리기 | 항상 최신 | 느리고, 사용자가 몰리면 백엔드 호출도 같이 늘어남 |
| B. 예전 방식 ISR(`revalidate = 60`) | 익숙함 | Next 16 기본 설정(cacheComponents)과 함께 쓸 수 없음 |
| C. Cache Components (선택) | Next 16 기본 방식. 데이터 함수 단위로 수명을 정함 | 새 방식이라 규칙이 낯섦 (아래 제약) |

결정: C.
- `frontend/src/lib/data.ts`의 데이터 함수에 `"use cache"` + `cacheLife("crowd")`(stale 60초 · revalidate 60초 · expire 1시간, `next.config.ts`). 실패한 결과는 `cacheLife("seconds")`로 짧게만 기억한다.
- `generateStaticParams`는 `src/data/places.json`의 121곳을 돌려준다. 백엔드가 꺼져 있어도 빌드가 된다.
- 없는 코드: Cache Components에서는 `dynamicParams = false`를 못 쓰고, 페이지 안의 `notFound()`는 껍데기가 먼저 나간 뒤라 상태가 200이 된다. 그래서 `src/proxy.ts`가 목록에 없는 코드를 없는 주소로 돌려 404가 나가게 했다.

- "다시 시도": 캐시에 이름표(`cacheTag("crowd")`)를 달고, 버튼이 서버 동작으로 그 캐시를 비운 뒤 다시 불러온다(T-006).
- 사이트 주소(SITE_URL)는 sitemap · robots · 공유 주소가 빌드 때 만들어지므로 빌드할 때 넣는다(T-007).

제약: 프론트가 장소 목록(코드 · 이름)을 따로 들고 있다. 백엔드 시드와 어긋나지 않게 같은 스크립트가 두 파일을 만들고, 백엔드 테스트가 둘이 같은지 확인한다.
바꿔야 하는 조건: 장소 수가 수천 곳이 되면 인기 장소만 미리 만들고 나머지는 첫 방문 때 만든다.
