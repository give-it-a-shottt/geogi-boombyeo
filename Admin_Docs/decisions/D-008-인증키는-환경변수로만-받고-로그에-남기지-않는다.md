# D-008 인증키는 환경변수로만 받고 로그에 남기지 않는다

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]

무엇을: 서울시 인증키는 환경변수(SEOUL_API_KEY)로만 받는다. 서울시 API는 인증키를 주소 안에 넣는 방식이라, 요청 주소가 로그나 DB에 남지 않게 막았다.
왜: 인증키가 로그 파일이나 오류 메시지에 찍히면 그 파일을 보는 누구나 키를 쓸 수 있다.

## 개발자 상세

막은 곳 (`backend/app/collector/client.py`)
- httpx는 기본으로 요청 주소를 INFO 로그에 찍는다 → 모듈을 불러올 때 `httpx` · `httpcore` 로거를 WARNING으로 올린다. 워커뿐 아니라 테스트 · 스크립트에서도 적용된다.
- httpx 예외의 원문에는 주소가 들어 있다 → 예외 종류 이름만 꺼내 `SeoulApiError("연결 실패 ConnectError")`처럼 새 메시지를 만든다.
- DB의 `last_error`에는 이 짧은 메시지만 저장한다.
- 인증키는 워커만 쓴다. 프론트와 조회 API는 키를 모른다. 도커 구성에서도 `SEOUL_API_KEY`는 worker 서비스에만 넘긴다(1차 리뷰 R2).
- 설정의 `seoul_api_key`는 `SecretStr`이다. 설정 객체를 실수로 로그에 찍어도 값이 가려진다. 실제 값은 주소를 만드는 한 곳(`service.py`)에서만 꺼낸다.
- 예상하지 못한 예외도 종류 이름만 기록한다(`처리 실패 RuntimeError`). 원문에 주소가 들어 있을 수 있기 때문이다.

확인: `tests/test_collector.py`가 로그와 오류 메시지에 키가 없는지 검사한다(이 테스트가 실제로 유출을 잡았다 → T-001).
제약
- 누군가 로깅 설정을 DEBUG로 바꾸고 httpx 로거 수준을 다시 내리면 주소가 찍힌다.
- 서울시 API는 https를 지원하지 않는다(2026-11-23에 https 접속을 시도했으나 연결되지 않음). 그래서 인증키가 든 주소가 암호화되지 않은 채 나간다. 서울시 쪽이 바뀌기 전에는 우리가 고칠 수 없다. 키가 유출되면 서울 열린데이터광장에서 다시 발급받는다.
