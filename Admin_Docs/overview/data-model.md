# 데이터 구조

## 한눈에 보기 (코드 몰라도 OK)
상태: [통과]

무엇을: 표가 네 개다. **장소**(121곳의 이름 · 분류 · 좌표), **스냅샷**(5분마다 쌓이는 혼잡도 기록), **예측**(장소마다 앞으로 12시간), **최신 상태**(장소마다 지금 값 한 줄과 수집 실패 기록).
비유: 스냅샷은 매일 적는 가계부(지우지 않고 쌓는다), 최신 상태는 가계부 맨 위에 적어 둔 "현재 잔액"이다. 화면은 잔액만 보면 되니 빠르다.

왜: 화면은 "지금 값"만 필요하고, 나중에 만들 요일 · 시간대 패턴은 "쌓인 기록"이 필요하다. 둘을 한 표에 두면 화면이 매번 최신 줄을 찾아야 해서 나눴다.

## 개발자 상세

정의: `backend/app/models.py`, 만드는 절차: `backend/alembic/versions/0001_initial.py` (둘이 같은지는 `tests/test_seed_and_schema.py`가 확인한다)

### places — 장소 (121줄, 시드)
| 필드 | 타입 | 설명 |
|---|---|---|
| code | 문자 10, 기본키 | 서울시 장소 코드 (예: POI009) |
| name | 문자 100, UNIQUE | 공식 이름. 서울시 API를 부를 때 이 이름을 쓴다 |
| category | 문자 30, 색인 | 원본 분류명 (화면 표기는 `levels.py`에서 바꾼다) |
| eng_name | 문자 200 | 영문 이름 (검색용) |
| lat, lng | 실수 | 영역 다각형의 무게중심 (D-005) |

### snapshots — 혼잡도 원본 (계속 쌓임, 하루 최대 약 3.5만 줄)
| 필드 | 타입 | 설명 |
|---|---|---|
| id | 정수, 기본키 | |
| place_code | 외래키 → places (CASCADE) | |
| observed_at | 시각(UTC) | 서울시가 잰 시각 |
| collected_at | 시각(UTC) | 우리가 받아 온 시각 |
| level | 정수 1 ~ 4 (CHECK) | 혼잡도 단계 |
| ppltn_min, ppltn_max | 정수, 비어도 됨 | 추정 인구 범위 |

제약: `UNIQUE(place_code, observed_at)` — 같은 관측 값을 두 번 쌓지 않는다. 이 제약이 (장소, 시각) 색인 역할도 한다.

### forecasts — 장소별 최신 예측 (장소마다 최대 12줄)
기본키 `(place_code, forecast_time)`, `level` 1 ~ 4, `ppltn_min/max`. 수집할 때마다 그 장소의 예측을 지우고 새로 넣는다. 지난 예측은 보관하지 않는다.

### place_status — 장소별 최신 상태 (장소마다 1줄)
| 필드 | 설명 |
|---|---|
| place_code | 기본키, 외래키 → places |
| level, ppltn_min, ppltn_max, observed_at | 마지막으로 성공한 값. 한 번도 성공하지 못했으면 비어 있다 |
| last_success_at | 마지막 성공 시각 |
| last_attempt_at | 마지막 시도 시각 (NOT NULL) |
| fail_count | 연속 실패 횟수 (성공하면 0) |
| last_error | 마지막 실패 사유 (200자까지, 인증키 · 주소는 넣지 않는다) |

### 규칙
- 시각은 전부 UTC로 저장하고(`db.py`의 `UTCDateTime`), 말로 바꿀 때만 한국 시간으로 바꾼다.
- 수집 실패는 마지막 성공 값을 지우지 않는다. 관측 시각이 60분보다 오래되면 조회 쪽에서 "지연"으로 판정한다.
- 시드에서 빠진 장소는 DB에서 지우지 않는다(쌓인 기록 보호).
