# T-008 아무것도 안 띄운 서버가 메모리를 절반 넘게 씀

## 한눈에 보기 (코드 몰라도 OK)
무슨 문제였나: 아무것도 띄우지 않은 1GB 서버가 이미 505MB를 쓰고 있어서, 서비스를 올릴 여유가 455MB밖에 없었다.
어떻게 해결했나: 무엇이 쓰는지 순서대로 뽑아 보니 `fwupd`라는 프로그램 하나가 200MB였다. 클라우드 서버에서는 쓸모가 없는 프로그램이라 껐고, 여유가 629MB로 늘었다.

## 개발자 상세
- 증상: `free -h` → 전체 961Mi, 사용 505Mi, available 455Mi (도커 미설치, 서비스 없음)
- 찾은 방법: `ps aux --sort=-%mem | head -8` → `/usr/libexec/fwupd/fwupd`가 RSS 약 200MB(20.3%)
- 원인: fwupd는 실제 부품(메인보드, SSD)의 펌웨어를 업데이트하는 프로그램이다. 가상 서버에는 업데이트할 부품이 없는데 Ubuntu 기본 설치에 들어 있어 떠 있었다.
- 해결: `systemctl stop fwupd` → `systemctl mask fwupd`(다시 켜지지 않게) → `systemctl disable --now fwupd-refresh.timer`. 결과 available 629Mi.
- 그대로 둔 것: `nbpmon`(네이버 클라우드 모니터링, 약 50MB), `unattended-upgrade`(보안 업데이트)
- 되돌리기: `sudo systemctl unmask fwupd`
- 배운 것: 메모리가 모자랄 때는 추측하지 말고 많이 쓰는 순서로 뽑아 본다.
