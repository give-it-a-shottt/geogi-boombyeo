# T-004 없는 장소 주소가 404가 아니라 200으로 응답

## 한눈에 보기 (코드 몰라도 OK)
무슨 문제였나: 없는 장소 주소(`/place/POI999`)를 열면 "찾는 장소가 없어요" 화면은 나오는데, 서버가 보내는 상태 코드는 "정상(200)"이었다. 검색엔진은 상태 코드를 보기 때문에 없는 페이지를 있는 페이지로 기록하게 된다.
어떻게 해결했나: 요청이 페이지에 닿기 전에 장소 코드를 121곳 목록과 비교해서, 없으면 처음부터 404로 응답하게 했다.

## 개발자 상세
- 증상: curl로 `/place/POI999`의 상태 코드를 찍으면 200
- 원인: Next 16 Cache Components + Partial Prefetching에서는 목록에 없는 주소를 열면 공통 껍데기(HTML 앞부분)를 먼저 보낸다. 그 뒤 페이지 안에서 `notFound()`를 불러도 상태 코드는 이미 200으로 나간 뒤다. 예전 방식의 `dynamicParams = false`는 Cache Components에서 쓸 수 없다(Next 내장 문서 `dynamicParams.md`).
- 해결: `frontend/src/proxy.ts`(matcher `/place/:code`)가 `src/data/places.json`에 없는 코드를 존재하지 않는 내부 주소로 rewrite → Next가 `not-found.tsx`를 404로 내보낸다.
- 덤으로 고친 것: 처음에는 코드를 `decodeURIComponent`로 풀었는데 `/place/%ZZ`에서 예외가 나 500이 됐다. 코드는 영문 · 숫자뿐이라 풀지 않고 그대로 비교하게 바꿨다.
- 확인: `/place/POI009` 200, `/place/POI999` 404, `/place/POI009/extra` 404
- 관련: F-003, D-006
