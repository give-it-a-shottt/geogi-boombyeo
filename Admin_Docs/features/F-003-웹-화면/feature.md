## 설계 의도 (AI 대리 작성 — 사용자 위임, 2026-11-23)
- 이 기능이 해결하는 문제: 출발 전에는 "몇 시에 갈까", 현장에서는 "여기 말고 어디"를 2번 안에 눌러 알 수 있어야 한다.
- 완료 기준:
  1. 디자인 md의 1차 화면 9개(HOM, SRC 2개, PLC 3개, CMN, INF, ERR)가 주소 · 상태로 구현된다.
  2. 장소 121곳 페이지가 빌드 때 만들어지고 sitemap에 들어간다.
  3. 없는 장소 주소는 실제 404 상태로 응답한다.
  4. 홈 하단 버튼: 위치 허용 → 근처 대안 시트, 거부 · 실패 → 검색 화면.
  5. 상세 하단 버튼: 여유 · 보통은 길찾기 하나, 약간 붐빔 · 붐빔은 길찾기 + 근처 덜 붐비는 곳.
  6. 백엔드가 응답하지 않아도 화면이 깨지지 않고 "불러오지 못했어요 / 다시 시도"를 보여 준다.
  7. 브라우저는 백엔드 주소를 모른다(같은 주소의 /api로만 요청).
- 화면: overview/screens.md
- API: F-002의 7개 중 health를 뺀 6개를 사용
- 데이터: 없음 (최근 검색어만 브라우저 localStorage)

## 결과 (AI 작성 — 구현 후)
- 바뀐 파일: `frontend/` 전체 — `src/app/`(페이지 · 중계 · sitemap · robots), `src/proxy.ts`, `src/components/`, `src/lib/`(리뷰 뒤 relay.ts · cache-tags.ts 추가), `src/app/actions.ts`(리뷰 뒤 추가), `src/data/places.json`, `next.config.ts`
- 실제 구조: 서버 컴포넌트가 `lib/data.ts`(use cache, 1분)로 읽어 HTML을 미리 만든다. 그래프 전환 · 시트 · 검색 · 전체 목록 · 기준 시각만 클라이언트 컴포넌트다. 목록 줄은 `PlaceRow` 하나, 답 영역은 `AnswerHero` 하나.
- 확인: `npm test`(9개) · `typecheck` · `lint` · `build` 통과(장소 121곳 사전 생성), `next start`로 주요 주소의 상태 코드 · 보안 헤더 · 글자 확인, 백엔드를 끈 화면과 다시 켠 뒤 회복 확인, 375 · 360 폭 스크린샷 확인(2026-11-23)
- 확인하지 못한 것: 위치 허용/거부 흐름과 "다시 시도" 버튼을 브라우저에서 직접 누르는 동작, 도커 구성
- 설계 의도와 다른 점
  - 계획의 "rewrite로 중계"를 route handler로 바꿈(D-007).
  - 계획의 "ISR revalidate 60"을 Cache Components 방식으로 바꿈(D-006). Next 16.4 기본 설정이 이 방식이다.
  - 로딩 화면(스켈레톤)은 Suspense fallback으로 구현. 데이터가 미리 만들어져 있어 실제로는 거의 보이지 않는다.
  - 1차에서 뺀 것: 공유 미리보기(OG) 이미지, 태블릿 · PC 전용 레이아웃
  - 리뷰 뒤 바꾼 것: 중계에 허용 경로 목록(D-007), "다시 시도"가 서버 캐시를 비움(T-006), 사이트 주소를 빌드할 때 받음(T-007), 위치 좌표를 소수 셋째 자리까지만 보냄, 보안 헤더
