## 지적
- [주의] [확실] "다시 시도" 버튼(RetryButton)이 서버 캐시를 건드리지 못한다. `router.refresh()`는 서버 쪽 "use cache"를 무효화하지 않는다(Next 내장 문서 use-router.md). 데이터 지연 안내의 "다시 시도"는 캐시 수명 60초 동안 같은 데이터가 다시 나온다. 백엔드 실패 때 첫 재시도가 같은 실패를 보일 수 있다는 부분은 [추정]. — src/components/actions.tsx `RetryButton`, src/lib/data.ts, src/components/parts.tsx — 확인한 범위: actions.tsx, data.ts, parts.tsx, next.config.ts, Next 문서 — 고치는 방법: data.ts에 cacheTag를 달고 다시 시도 때 서버 액션에서 캐시를 무효화한 뒤 새로 고친다. 또는 문구가 즉시 갱신을 약속하지 않게 바꾼다.
- [주의] [확실] 예외 경로가 실행으로 확인되지 않았고 테스트도 없다. 백엔드를 끈 상태는 실행으로 확인하지 못했다(완료 기준 6). 테스트는 time.ts 3개뿐이고, 중계(route.ts)의 400 · 502 · 상태 코드 전달, data.ts의 null 분기, proxy.ts는 테스트가 없다. — 테스트 전반 — 확인한 범위: time.test.ts, 패킷의 테스트 결과 — 고치는 방법: 백엔드를 끈 채 주요 주소를 직접 확인해 기록하고, 중계 GET의 400/502/상태 코드 전달 테스트를 추가한다. time.ts에 잘못된 날짜 입력 케이스도 넣는다.
- [제안] [추정] 예측 구간 인덱스가 범위를 벗어나면 화면 전체가 error.tsx로 떨어진다(`timeline[recommend.start_index].level`을 검사 없이 읽음). 확인하면 확실해지는 것: 백엔드 recommend 생성부의 범위 보장 여부. — src/components/ForecastChart.tsx — 확인한 범위: ForecastChart.tsx, types.ts, api-list.md — 고치는 방법: 범위를 벗어나면 null로 취급하는 검사를 추가한다.
