## 지적
- [주의] [추정] 위치 정보가 백엔드 접속 로그에 남을 수 있다. 홈 버튼은 위도·경도를 소수 넷째 자리까지 쿼리로 보내고 중계는 쿼리를 그대로 넘긴다. uvicorn은 기본으로 접속 로그에 쿼리를 포함한 경로를 기록한다. 서비스 소개 화면의 "저장하지 않아요"와 맞지 않는다. 확인하면 확실해지는 것: nearby를 한 번 호출한 뒤 API 로그에 좌표가 찍히는지. — NearbyLauncher.tsx `load()`, route.ts `GET`, docker-compose.yml `api.command` — 확인한 범위: 이 세 파일과 about/page.tsx — 고치는 방법: uvicorn에 `--no-access-log`을 붙이고, 좌표는 소수 셋째 자리(약 110m)로 줄인다.
- [제안] [확실] 보안 응답 헤더가 없다. — next.config.ts — 확인한 범위: next.config.ts, route.ts — 고치는 방법: `headers()`로 nosniff, Referrer-Policy, frame-ancestors를 넣고 `poweredByHeader: false`로 둔다.
- [제안] [확실] 중계가 백엔드 `/api/` 아래 모든 경로를 그대로 연다. 나중에 내부용 GET이 생기면 자동으로 노출된다. — route.ts `GET` — 확인한 범위: route.ts, D-007 — 고치는 방법: 프론트가 쓰는 경로만 허용 목록으로 통과시킨다.
- [제안] [확실] 서버 전용 모듈(backend.ts, data.ts)에 클라이언트 import 방지 장치가 없다(지금은 import하는 곳 없음). — lib/backend.ts, lib/data.ts — 확인한 범위: "use client" 파일 7개의 import — 고치는 방법: `import "server-only"`를 넣는다.
- [제안] [확실] 중계 응답이 전부 no-store이고, 브라우저가 요청을 취소해도 백엔드 호출은 끝까지 간다. — route.ts `GET` — 확인한 범위: route.ts, AllPlaces.tsx, SearchScreen.tsx — 고치는 방법: `/api/places`에 짧은 캐시를 두고, upstream fetch에 요청의 취소 신호를 함께 준다.

체크리스트 밖 참고(판정에 넣지 않음, [추정]): Dockerfile은 빌드할 때 SITE_URL을 넣지 않아, `metadataBase`·sitemap.xml·robots.txt가 빌드 시점 기본값(localhost)으로 미리 만들어질 수 있다.

## 체크 항목별 근거
- XSS → dangerouslySetInnerHTML 없음, 검색어·장소 이름은 JSX 텍스트로 출력 → 문제 없음. 길찾기 주소는 Q-004 임시 처리와 관련
- 외부 링크 target/rel → 둘 다 `noopener noreferrer` → 문제 없음
- 토큰 저장 위치 → 해당 없음 (로그인 없음)
- localStorage → 최근 검색어 5개만, 읽을 때 검증 → 문제 없음
- 공개 환경변수 비밀값 노출 → NEXT_PUBLIC_ 사용 없음 → 문제 없음
- 권한 없는 화면 접근 차단 → 해당 없음
- 위치 정보 → 버튼을 누를 때만 받고 클라이언트에 저장하지 않음. 백엔드 로그는 [주의]
- 보안 헤더 → 없음 ([제안])
- 중계 SSRF·경로 조작 → 호스트 고정, `.`/`..` 차단, 허용 문자 검사와 재인코딩 → 문제 없음
- 쿼리 전달 → 호스트를 바꿀 수 없어 SSRF 없음. 서버 쪽 검증은 백엔드 몫이라 미확인
- 응답 헤더 전달 → content-type과 cache-control만 내보냄 → 문제 없음
- 입력 검증(proxy) → 목록과 정확히 일치할 때만 통과 → 문제 없음
- 인증과 권한 · SQL 인젝션 → 해당 없음
- CORS → 헤더를 붙이지 않음(같은 출처 전용) → 문제 없음
- 비밀키 하드코딩 → 없음. .env는 이미지에서 빠짐
- 에러 응답 내부 정보 노출 → 일반 문구만 → 문제 없음
- 패키지 취약점·버전 → next 16.4.6, react 19.3.0, npm audit 0건(메인 실행 결과) → 문제 없음
- Admin_Docs·코드 민감 정보 → 없음
- 컨테이너 → node 사용자, standalone, 3000 포트만 공개 → 문제 없음
- 캐시: 실패 결과 → `seconds`로 짧게만 기억 → 문제 없음
- 캐시 폭주·키 폭증 → 캐시 키가 121곳 코드로 제한됨 → 문제 없음
- 과도한 API 호출 → 디바운스와 취소, 로딩 중 재요청 막음 → 문제 없음. 중계에서 upstream을 취소하지 않는 점은 [제안]
